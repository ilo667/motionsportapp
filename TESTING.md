# Manual Testing Checklist

Тест-кейси що покрито unit тестами — перевір вручну після деплою.

---

## 1. Вікно бронювання (14:00 – 21:00)

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 1.1 | До 14:00 — запис закритий | Увійди як клієнт до 14:00 (або Demo → "До 14:00") | Замість кнопки "Записатись" — текст "Запис відкриється о 14:00" |
| 1.2 | Після 21:00 — запис закритий | Demo → "Після 21:00" | Текст "Запис закрито", кнопок немає |
| 1.3 | О 14:00 — запис відкривається | Demo → "Запис відкрито" | Кнопка "Записатись" активна |
| 1.4 | О 21:00 — запис закривається | Виставити час 21:00 | Кнопки зникають |

---

## 2. Бронювання — валідація слоту

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 2.1 | Слот повний | Demo → "Повний слот", слот 19:00 = 8/8 | Кнопки "Записатись" немає, є "Сповістити про вільне місце" |
| 2.2 | Подвійний запис | Записатись на 19:00, потім спробувати записатись на 20:00 через devtools або API | Помилка "already have an active booking" |
| 2.3 | Слот скасовано тренером | Тренер скасовує слот → клієнт перезавантажує сторінку | Текст "Скасовано", кнопок немає |

---

## 3. Скасування і переключення

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 3.1 | Скасувати запис | Записатись → натиснути "Скасувати" → вибрати причину | Запис зникає, слот показує на 1 менше |
| 3.2 | Перейти на інший час | Записатись на 19:00 (є вільне місце на 20:00) → "Перейти на 20:00" | Запис переноситься, на 19:00 звільняється місце |
| 3.3 | Скасування після 21:00 неможливе | Записатись, дочекатись 21:00 або Demo → "Після 21:00", спробувати скасувати | Помилка "Booking window has closed" |

---

## 4. Оголошення тренера

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 4.1 | Оголошення не показується до 14:00 | Тренер публікує оголошення → Demo → "До 14:00" → клієнт відкриває сторінку | Оголошення відсутнє |
| 4.2 | Оголошення показується після 14:00 | Тренер публікує оголошення → Demo → "Запис відкрито" → клієнт | Текст оголошення відображається |
| 4.3 | Чернетка не показується | Тренер пише текст але НЕ натискає "Опублікувати" → клієнт | Оголошення відсутнє |
| 4.4 | Оголошення зникає після 21:00 | Було опубліковано → Demo → "Після 21:00" | Оголошення не відображається |
| 4.5 | Тренер може змінити оголошення після публікації | Опублікувати → змінити текст → опублікувати знову | Клієнт бачить новий текст |

---

## 5. AI-генерація оголошення

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 5.1 | Згенероване оголошення без назви залу | Адмін → "Згенерувати оголошення" | Текст НЕ містить "MotionSport", "Motion Gym" або будь-якої назви |
| 5.2 | Fallback при недоступності AI | Вимкнути GEMINI_API_KEY в env → генерувати | Показується стандартний текст запрошення, без помилки |

---

## 6. Адмін-панель — управління слотами

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 6.1 | Відмінити тренування | Адмін → кнопка "Відмінити тренування" → підтвердити | Слот отримує статус "Скасовано", записані клієнти отримують push |
| 6.2 | Підтвердити відвідування | Адмін → натискати кнопку "—" біля імені → змінюється на "✓" → "✗" → "—" | Цикл змінюється коректно |
| 6.3 | Підтвердити всіх | Адмін → "Підтвердити всіх" | Всі учасники отримують "✓" |

## 7. Demo режим

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 7.1 | До 14:00 | Demo Controls → "До 14:00" | Запис закритий на обох слотах |
| 7.2 | Запис відкрито | Demo Controls → "Запис відкрито" | Слот 19:00 = 7/8, 20:00 = 3/8, кнопки активні |
| 7.3 | Повний слот | Demo Controls → "Повний слот" | Слот 19:00 = 8/8, кнопка vacancy alert |
| 7.4 | Після 21:00 | Demo Controls → "Після 21:00" | "Запис закрито" на всіх слотах |
| 7.5 | Скидання | Demo Controls → Reset | Повертається до початкового стану |

## Команда для запуску unit тестів

```bash
cd backend && npm test
```

Всі 25 тестів мають проходити перед кожним деплоєм.
