## 10. LiqPay — оплата індивідуальних/спліт тренувань

Перед тестуванням застосувати міграцію (якщо ще не застосована):
```bash
node backend/scripts/migrate-payments.js
```

Env vars для тестування:
- `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY` — тестова пара ключів (починаються з `sandbox_`). Режим визначається лише ключами — з `sandbox_` реальних списань немає
- `LIQPAY_SERVER_URL` — публічний URL `/payments/liqpay/callback` (без `/api`!)
- `FRONTEND_URL` — адреса фронтенду, інакше LiqPay не покаже кнопку повернення

Тестові картки: https://www.liqpay.ua/uk/doc/api/testing (CVV будь-який, термін — будь-яка майбутня дата)

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 10.1 | Кнопка "Оплатити 700 ₴" для інд/спліт | Тренер додає слот з типом "Індивідуальні" або "Спліт" → клієнт відкриває розклад | Замість "Записатись" — кнопка "Оплатити 700 ₴" |
| 10.2 | Кнопка "Записатись" для групових | Слот типу "Групові" | Стандартна кнопка "Записатись" без оплати |
| 10.3 | Редирект на LiqPay | Натиснути "Оплатити 700 ₴" | Браузер переходить на сторінку LiqPay із формою оплати |
| 10.4 | Статус "Очікує оплати" | Після редиректу на LiqPay закрити вкладку → повернутись у розклад | Власний запис показує "Очікує оплати" + кнопка повторної оплати |
| 10.4a | Повторна оплата з розкладу | У стані 10.4 натиснути "Оплатити 700 ₴" → оплатити `4242…` | Редирект на LiqPay (не 409), лічильник місць не змінюється; після оплати "✓ Оплачено". Старе замовлення в БД — `REPLACED` |
| 10.4b | Оплата у старій вкладці | 10.4a, але оплатити у першій (старій) вкладці LiqPay | Запис все одно стає "✓ Оплачено" (callback для `REPLACED`, поки запис чекає оплати) |
| 10.5 | Успішна оплата | Картка `4242424242424242` → callback `/payments/liqpay/callback` | Статус змінюється на "✓ Оплачено", запис активний |
| 10.6 | Сторінка повернення після успіху | Картка `4242…` → "Повернутися на сайт" | `/payment/return`: лоадер → "✓ Платіж прийнято" |
| 10.11 | Неуспішна оплата | Картка `4000000000000002` (limit) → "Повернутися на сайт" | `/payment/return`: "✕ Оплата не пройшла"; у розкладі запис скасовано, знову кнопка "Оплатити 700 ₴". Callback на невдалу спробу LiqPay не шле — статус береться з LiqPay status API |
| 10.12 | Повернення без оплати | Відкрити LiqPay → одразу "Повернутися на сайт" | "Оплату не завершено" (через ~10 с перевірок), запис лишається "Очікує оплати" |
| 10.7 | Невалідний callback (неправильний підпис) | POST `/payments/liqpay/callback` з неправильними даними | `{"ok": false}`, запис не змінюється |
| 10.8 | Прострочений PENDING | Не платити 15+ хвилин → відкрити розклад | Запис скасовується, місце звільняється (перед скасуванням бекенд звіряє статус з LiqPay) |
| 10.9 | Слот групових не створює checkout | POST `/payments/checkout` для групового слоту | 400 "does not require payment" |
| 10.10 | Повний слот | Спробувати оплатити повний слот | 409 Conflict |
