## 9. Адмін-календар

Перед тестуванням застосувати міграції:
```bash
psql $DATABASE_URL -f backend/sql/add-training-type.sql
psql $DATABASE_URL -f backend/sql/add-training-type-to-slots.sql
```

Перед тестуванням персональних тренувань застосувати міграцію (якщо ще не застосована):
```bash
node backend/scripts/migrate-personal-slots.js
```

Кожен **слот** — окрема подія в календарі. Групові завжди 19:00 і 20:00, їх бачать усі. Індивідуальне (1 людина) і спліт (1–3 людини) — на будь-який час з кроком 15 хв, їх бачать тільки вибрані люди. В один день можна мати групові, кілька індивідуальних і кілька сплітів.

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 9.1 | Перехід до календаря | Адмін → посилання "Календар" в хедері | Відкривається `/admin/calendar` з видом **"Тиждень"** (шкала 17:00–22:00, тиждень з понеділка) |
| 9.1a | Перемикання виду | Кнопки "Тиждень" / "Місяць" справа в тулбарі | Вид перемикається; стрілки ‹ › гортають тижні / місяці |
| 9.1b | Тиждень на межі місяців | Тиждень, що захоплює два місяці (напр. 26 жовт – 1 лист) | Видно тренування з обох місяців; заголовок "26 жовт. – 1 лист.", кнопки "Тиждень / Місяць" в одному рядку з ним |
| 9.2 | Наявні слоти відображаються | Відкрити місяць з існуючими training_slots | Кожен активний слот = кольорова подія на своїй годині з підписом "Груп. · 3/8"; персональні з іменами: "Інд. · 0/1 · Катя", "Спліт · 1/3 · Катя, Оля"; заливка кольором типу, не прозора — і в "Тиждень", і в "Місяць" |
| 9.3 | Колір за типом | Групові = зелений, Індивідуальні = жовтий, Спліт = помаранчевий | Кольори відповідають легенді вгорі |
| 9.4 | Додати групові | Клік на порожню клітинку майбутнього дня (у виді "Тиждень" клік на 20:00 одразу підставляє 20:00) → вибрати "Групові" → Зберегти | Створюються обидва слоти 19:00 і 20:00 з типом "Групові" |
| 9.5 | Додати індивідуальне | Клік на день → "Індивідуальні" → ввести час (напр. 10:30) → вибрати людину → Зберегти | Жовта подія 10:30 "Інд. · 0/1 · Ім'я"; тижневий вид розширюється, щоб показати 10:00 |
| 9.5a | Індивідуальне без часу або людини | "Індивідуальні" → не вводити час / не вибрати людину → Зберегти | "Вкажіть час з кроком 15 хвилин…" / "Виберіть людину", нічого не створюється |

| 9.6 | Додати спліт | Клік на день → "Спліт" → час → Людина 1 обовʼязкова, Людина 2 і 3 за бажанням → Зберегти | Помаранчева подія "Спліт · 0/3 · імена" (місць завжди 3); в іншому списку вже вибрані люди не повторюються |
| 9.6a | Кілька тренувань в один день | В один день додати групові, два індивідуальні (різний час) і спліт — кожне окремим кліком на день | Усі події на своїх годинах |
| 9.6b | Зайнятий час | Додати індивідуальне на 19:00 у день з груповими (або на час, де вже є персональне) | "На цей час уже є тренування" |
| 9.6c | Минулий час | Сьогодні додати індивідуальне на годину, що вже минула | "Цей час уже минув" |
| 9.7 | Змінити людей у персональному | Клікнути по персональній події → змінити людей → Зберегти | Імена в події оновлюються, кількість місць не змінюється |

| 12.10 | День лише з персональними | Сьогодні є тільки персональне (без групових) | О 14:00 push "запис відкрито" не надсилається, оголошення не генерується |

## 10. LiqPay — оплата індивідуальних/спліт тренувань

Перед тестуванням застосувати міграцію (якщо ще не застосована):
```bash
node backend/scripts/migrate-payments.js
```

Env vars для тестування:
- `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY` — тестова пара ключів (починаються з `sandbox_`). Режим визначається лише ключами — з `sandbox_` реальних списань немає
- `LIQPAY_SERVER_URL` — публічний URL `/payments/liqpay/callback` (без `/api`!)
- `FRONTEND_URL` — адреса фронтенду, інакше LiqPay не покаже кнопку повернення
- `PAYMENT_EXPIRY_MINUTES` — через скільки хвилин неоплачений запис скасовується (за замовчуванням 15). Для тестів став `2`, після тестів — прибери
