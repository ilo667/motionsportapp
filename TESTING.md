## 1. Вікно бронювання (14:00 – 21:00)

Демо-режиму більше немає: час завжди реальний (Київ). Стани вікна перевіряються в реальний час дня тренування (групові Пн/Ср/Пт).

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 1.1 | До 14:00 — запис закритий | Увійди як клієнт у день тренування до 14:00 | Замість кнопки "Записатись" — текст "Запис відкриється о 14:00" |
| 1.2 | Після 21:00 — запис закритий | Відкрити розклад у день тренування після 21:00 | Текст "Запис закрито", кнопок немає |
| 1.3 | О 14:00 — запис відкривається | Відкрити розклад у день тренування між 14:00 і 21:00 | Кнопка "Записатись" активна |
| 1.4 | О 21:00 — запис закривається | Тримати сторінку відкритою до 21:00 | Кнопки зникають |
| 1.5 | Оновлення у вікні запису | Між 14:00 і 21:00 → DevTools → Network, фільтр `schedule` | `GET /api/schedule/next` кожні ~5 с |
| 1.6 | Оновлення поза вікном | До 14:00 або після 21:00 → Network | Запити рідко: раз на 5 хв (або в момент відкриття/закриття запису, якщо він ближче) |
| 1.7 | Відкриття запису о 14:00 | Тримати сторінку відкритою з 13:55 | О 14:00 (±1 с) один запит, далі кожні ~5 с, без очікування 5 хв |
| 1.8 | Фонова вкладка | Перейти на іншу вкладку на 1 хв → повернутись | Поки вкладка прихована — запитів немає; при поверненні — одразу один запит і далі за розкладом |

## 6. Адмін-панель — управління слотами

Навігація тренера — бургер-меню справа в хедері (однакове на телефоні й десктопі): "Панель тренера", "Клієнти", "Календар", "Вийти". Поточна сторінка підсвічена зеленим; меню закривається кліком поза ним, Escape або вибором пункту.

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 6.1 | Відмінити тренування | Адмін → кнопка "Відмінити тренування" → підтвердити | Слот отримує статус "Скасовано", записані клієнти отримують push |
| 6.2 | Підтвердити відвідування | Адмін → натискати кнопку "—" біля імені → змінюється на "✓" → "✗" → "—" | Цикл змінюється коректно |
| 6.3 | Підтвердити всіх | Адмін → "Підтвердити всіх" | Всі учасники отримують "✓", кнопка замінюється текстом "✓ Всі учасники підтверджені". Окремі відмітки після цього **можна змінювати** (виправити помилку) |
| 6.4 | Автопідтвердження о 22:00 | Не підтверджувати відвідуваність → дочекатись спрацювання cron `/internal/cron/auto-confirm-attendance` | Всі UNMARKED бронювання отримують PRESENT автоматично |
| 6.5 | Cron доходить до коду | `cd backend && vercel crons run /internal/cron/booking-open` → `vercel logs requests` | `GET /internal/cron/booking-open 200` з `vercel-cron/1.0` (не 404). Без `CRON_SECRET` на Vercel — 403 |

## 9. Адмін-календар

Перед тестуванням застосувати міграції:
```bash
psql $DATABASE_URL -f backend/sql/add-training-type.sql
psql $DATABASE_URL -f backend/sql/add-training-type-to-slots.sql
```

Перед тестуванням персональних тренувань застосувати міграцію (якщо ще не застосована):
```bash
node backend/scripts/migrate-assigned-slots.js
```

Кожен **слот** — окрема подія в календарі. Групові завжди 19:00 і 20:00, їх бачать усі. Персональне (1 людина) і спліт (1–3 людини) — на будь-який час з кроком 15 хв, їх бачать тільки вибрані люди. В один день можна мати групові, кілька персональних і кілька сплітів.

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 9.1 | Перехід до календаря | Адмін → бургер-меню в хедері → "Календар" | Відкривається `/admin/calendar` з видом **"Тиждень"** (шкала 17:00–22:00, тиждень з понеділка) |
| 9.1a | Перемикання виду | Кнопки "Тиждень" / "Місяць" справа в тулбарі | Вид перемикається; стрілки ‹ › гортають тижні / місяці |
| 9.1b | Тиждень на межі місяців | Тиждень, що захоплює два місяці (напр. 26 жовт – 1 лист) | Видно тренування з обох місяців; заголовок "26 жовт. – 1 лист.", кнопки "Тиждень / Місяць" в одному рядку з ним |
| 9.2 | Наявні слоти відображаються | Відкрити місяць з існуючими training_slots | Кожен активний слот = кольорова подія на своїй годині з підписом "Груп. · 3/8"; персональні з іменами замість числа, ✓ = оплачено: "Перс. · Катя", "Спліт · Катя ✓, Оля"; заливка кольором типу, не прозора — і в "Тиждень", і в "Місяць" |
| 9.3 | Колір за типом | Групові = зелений, Персональні = жовтий, Спліт = помаранчевий | Кольори відповідають легенді вгорі |
| 9.4 | Додати групові | Клік на порожню клітинку майбутнього дня (у виді "Тиждень" клік на 20:00 одразу підставляє 20:00) → вибрати "Групові" → Зберегти | Створюються обидва слоти 19:00 і 20:00 з типом "Групові" |
| 9.5 | Додати персональне | Клік на день → "Персональні" → ввести час (напр. 10:30) → вибрати людину → Зберегти | Жовта подія 10:30 "Перс. · Ім'я"; тижневий вид розширюється, щоб показати 10:00 |
| 9.5a | Персональне без часу або людини | "Персональні" → не вводити час / не вибрати людину → Зберегти | "Вкажіть час з кроком 15 хвилин…" / "Виберіть людину", нічого не створюється |
| 9.5b | Час не кратний 15 хв | Ввести 10:10 | "Вкажіть час з кроком 15 хвилин…" |
| 9.6 | Додати спліт | Клік на день → "Спліт" → час → Людина 1 обовʼязкова, Людина 2 і 3 за бажанням → Зберегти | Помаранчева подія "Спліт · імена" (місць завжди 3); в іншому списку вже вибрані люди не повторюються |
| 9.6a | Кілька тренувань в один день | В один день додати групові, два персональні (різний час) і спліт — кожне окремим кліком на день | Усі події на своїх годинах |
| 9.6b | Зайнятий час | Додати персональне на 19:00 у день з груповими (або на час, де вже є персональне) | "На цей час уже є тренування" |
| 9.6c | Минулий час | Сьогодні додати персональне на годину, що вже минула | "Цей час уже минув" |
| 9.7 | Змінити людей у персональному | Клікнути по персональній події → змінити людей → Зберегти | Імена в події оновлюються, кількість місць не змінюється |
| 9.7b | Статус оплати в персональному | Спліт для Каті, Олі, Іри → Катя оплатила, Оля на сторінці LiqPay, Іра нічого → клікнути подію | Подія "Спліт · Катя ✓, Оля, Іра"; у модалці: Катя "оплачено", Оля "очікує оплати", Іра "не оплачено" (замість "Записано X з Y") |
| 9.7a | Прибрати людину, що вже оплатила | Людина оплатила спліт → тренер прибирає її зі списку → Зберегти | "Ця людина вже оплатила, її не можна прибрати" |
| 9.8 | Скасувати конкретне тренування | Клікнути по події → "Скасувати тренування 19:00" | Подія зникає, інші залишаються; хто був записаний — отримує push |
| 9.9 | Клік по минулому дню | Клікнути на день, що вже минув | Модалка не відкривається |
| 9.10 | Навігація по місяцях | Стрілки ← → в хедері | Дані підвантажуються для нового місяця |
| 9.11 | Повернення до панелі | Бургер-меню → "Панель тренера" | Повернення на `/admin` |

## 12. Мої тренування — клієнт

Тренер додає персональне або спліт у календарі й вибирає людей (див. 9.5–9.7).

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|
| 12.1 | Бачить тільки вибрана людина | Персональне для клієнта A → увійти як A, потім як B | В A на головній блок "Мої тренування" з карткою (час, день, "Персональне", "Оплатити 700 ₴"); у B блоку немає |
| 12.2 | Будь-який день | Персональне на день, коли групових немає (напр. вівторок) | A бачить його у "Мої тренування"; "Наступне тренування" лишається найближчим днем з груповими |
| 12.3 | Оплата до початку | A → "Оплатити 700 ₴" → картка `4242…` | Картка з зеленою рамкою і кнопкою "Скасувати"; вікно 14:00–21:00 не потрібне |
| 12.4 | Групове + персональне в один день | A оплатив персональне на 18:00 → записується на групове 19:00 того ж дня | Запис на групове проходить; обидва записи активні |
| 12.5 | Кілька персональних в один день | Два персональні для A в один день | Обидва можна оплатити незалежно |
| 12.6 | Спліт | Спліт для A і B | Обоє бачать картку "Спліт · 0/3 місць"; після оплати A — "1/3" |
| 12.7 | Скасування оплаченого | "Скасувати" → причина → підтвердити | Запис скасовано, місце вільне; гроші тренер повертає вручну. Групове того ж дня не зачіпається |
| 12.8 | Тренування почалося | Відкрити головну після початку персонального | Неоплачене: "Тренування вже почалося", без кнопки оплати. Оплачене: зелена рамка без "Скасувати". Через годину після початку картка зникає |
| 12.9 | Чужий слот через API | POST `/payments/checkout` зі slotId персонального слоту іншої людини | 404, запис не створюється |
| 12.10 | День лише з персональними | Сьогодні є тільки персональне (без групових) | О 14:00 push "запис відкрито" не надсилається, оголошення не генерується |

```bash

```

| # | Сценарій | Як відтворити | Очікуваний результат |
|---|----------|---------------|----------------------|

## 10. LiqPay — оплата персональних/спліт тренувань

Перед тестуванням застосувати міграцію (якщо ще не застосована):
```bash
node backend/scripts/migrate-payments.js
```

Env vars для тестування:
- `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY` — тестова пара ключів (починаються з `sandbox_`). Режим визначається лише ключами — з `sandbox_` реальних списань немає
- `LIQPAY_SERVER_URL` — публічний URL `/payments/liqpay/callback` (без `/api`!)
- `FRONTEND_URL` — адреса фронтенду, інакше LiqPay не покаже кнопку повернення
- `PAYMENT_EXPIRY_MINUTES` — через скільки хвилин неоплачений запис скасовується (за замовчуванням 15). Для тестів став `2`, після тестів — прибери

Тестові картки: https://www.liqpay.ua/uk/doc/api/testing (CVV будь-який, термін — будь-яка майбутня дата)
